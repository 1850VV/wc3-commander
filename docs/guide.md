# 使用与实现细节

把《魔兽争霸三》的运营拆成事件（建造、采集、生产），排在时间轴上，由程序替你下命令。
你在二维化的失落神庙地图上编排和调整，程序通过 [wc3env-127a](https://github.com/1850VV/wc3env-127a) 控制真实的 1.27a 游戏。

```
浏览器控制台（web/）            离线时：浏览器内模拟器预演整局
   ⇅ HTTP + 服务器推送事件
指挥官服务（bridge/）           事件 → wc3env 命令；游戏事件 → 时间轴状态
   ⇅ wc3env（实时模式）
魔兽争霸三 1.27a（Windows）
```

> 本文保留实现细节与旧控制台操作。新版入口、原型截图和功能状态见 [项目首页](../README.md)。

## 现在能做什么

- **真实地图**：失落神庙的通行网格（640×640，每格 32 游戏单位）、4392 棵树、12 座金矿、4 个出生点。
- **真实数值**：单位和建筑的造价、人口、工期、科技前置取自 1.27a 数据。
- **离线预演**：A* 寻路、建筑选址（避开采金路线）、金矿一次进一个农民、砍树和树木耗尽、人族建造需要农民在场。拖动时间轴上的事件，整局立刻按新编排重算。
- **二维指挥**：选中农民后按快捷键，在地图上点选位置放建筑；选中建筑训练单位；暂停的工地可以派人继续建。每个操作都变成时间轴上的一个事件。
- **摆工地**：地图上的工地框可以直接拖动。拖过的工地是「指定位置」（实线、带圆点），实战按这个坐标精确建造，比自动选的工地优先占位；没拖的是「自动选址」（虚线）。选中事件可以「恢复自动选址」。概览面板列出 30 秒内要开工的工地，点一下跳过去。建筑开工前都能改位置，实战中改了会重新下令。地图上建筑的**实心块**是真正挡路的范围（寻路贴图里的 `walk` 格），外面一圈**虚框**是不能建造、但单位能走的缓冲——所以实心块看起来比虚框小，尤其是在祭坛、兵营、大厅和金矿上。
- **封家**：概览面板按计划里全部工地的位置判断采金区能不能被英雄进来，地图上用圆圈标出最窄处。「自动封家」用计划里最早的祭坛、兵营和最多 4 个农场把采金区围起来，只留 2 格的缝（农民、步兵能过，英雄过不去），结果写成指定位置，之后还能手动拖。南方出生点 3 个农场就能封住；其他出生点在模拟里要 4 个，西方 4 个还差一点。**「2 格能过农民、3 格才过英雄」是按碰撞半径推算的（农民 16、步兵 31、英雄 32），还没在真游戏里验证。** 封住时面板会显示墙内还剩多少空地。
- **事件依赖**：选中事件后，命令面板里可以把「开始条件」设为「等某个事件完成」（建好、训练出来、升级完、开始采集都算完成），开始时间取计划时间和依赖完成时间中较晚的那个。删掉被依赖的事件，等它的事件会改回按计划时间开始。
- **升级**：「升级 主城 / 防御塔」，或选中建筑点「升级为…」。升级占用这座建筑的生产队列（升主城期间不能出农民，和游戏一致），花费是两种建筑的差价。
- **分矿**：地图上标出每个出生点的分矿（离主基地最近的另一座金矿）。「建造 分基地 N」在分矿旁建城镇大厅，开工后再派 N 个农民协助（每多一人约快 0.6 倍、多花 15%，是推算值，待实机核对），完工后这些农民就在分矿采金；「采金 N 分矿」把农民派去分矿。
- **民兵与清野**：「学 水元素」让大法师学技能；「敲钟 N」从伐木农民里抽 N 个，农民先走回城镇大厅变成民兵，45 秒后原地变回；「清野」带英雄、步兵和最近一次敲钟的民兵去清分矿。实战中由引擎的清野控制器指挥（`bridge/commander_bridge/combat.py`）：攻击移动过去，集火（暗影牧师等治疗单位优先），英雄有蓝就放水元素，民兵血量低于 35% 自动撤回，英雄低于 30% 全队撤退并判失败；你手动拉的单位会被让出 5 秒。失败的清野不会自动放行后面等它的事件（例如分基地）。模拟里清野不打仗，部队到了之后按估计时长（默认 40 秒）算清完。
- **人族速矿二本策略**：「载入布局…」里的「人族速矿二本 · 南方/西方/北方/东方」是按用户给的打法生成的整局编排（`tools/make_fast_expand.js` 可重新生成）：3 农采金、农民 4 祭坛、农民 5 农场、新农民兵营（祭坛、兵营、农场放在各出生点的封家位置），大法师首发学水元素，2:05 敲钟，清近矿后 4 人协助建分基地，分矿侦察塔升防御塔，5:45 升主城，之后山丘之王、神秘圣地和法师。时间轴延长到 10:00。
- **检查点**：策略里带打法的 10 条检查点（例如「1:00 国王祭坛完成」「3:00–3:40 分基地开工」），概览面板逐条显示按时 / 晚几秒 / 没达成。模拟结果：南、北、东 9–10 条按时；西方清野和分基地晚 20–50 秒（去分矿的路更远）。模拟里清野是估计时长，采金速度也没校准，到 10:00 剩下的钱偏多。
- **四个出生点的封家布局**：`strategies/` 里有「南出生点」（用户手摆）和照着同一思路生成的「西出生点」「北出生点」「东出生点」，旁边的图片是控制台截图。西、北各多 1 个农场，东多 2 个；都只在模拟里验证过封家。
- **布局的载入与保存**：顶部的「载入布局…」下拉框载入一套编排（会替换当前编排，并切到它的出生点）；载入后顶部显示「当前布局 名字」，改过（拖工地、加删事件、拖时间条）会显示「未保存」。「保存」直接写回这套 `strategies/名字.json`，不再问名字；要存成新的一套点「另存为…」。没载入任何布局时点「保存」会先问名字。文件在仓库里，可以通过 git 在两台电脑之间同步。服务端接口：`GET /api/strategies`、`GET /api/strategies/<名字>`、`PUT /api/strategies/<名字>`；计划推给服务时带 `name`，加入正在进行的游戏时控制台就显示服务挑的那套布局。
- **连接游戏**：指挥官服务把事件翻译成 wc3env 命令（`build`、`harvest`、`train`、`smart`），时间轴状态以游戏回报的 `construct_start/finish`、`train_start/finish` 事件为准，不把"命令被接受"当成"已完成"。
- **建筑位置**：在地图上亲手放的工地按精确坐标建造，不会被挪开；建不了会在时间轴上提示并重试，最多 4 次。其余工地交给游戏自带选址（可能挪开几百距离），引擎读取游戏回报的实际坐标来认领新建筑，不会因为挪远而重复建造。
- **AI 建议**：目前是规则引擎占位，之后换成大模型。

## 快速开始

### 1. 查看界面

最新版 `web/index.html` 要通过本地服务读取战术脚本，请按[首页的快速开始](../README.md#快速开始)启动。

旧控制台可以静态打开，只看浏览器内模拟器：

```sh
cd web
python -m http.server 8000
# 打开 http://127.0.0.1:8000/old.html
```

### 2. 用假游戏服务器跑通整条链路（任何系统，不需要魔兽）

需要 Python 3.11+ 和本地的 wc3env-127a 源码。在 Mac / Linux 上运行需要它的跨平台导入修复（`cross-platform-import` 分支：让协议、会话和假服务器不依赖 Windows 也能导入）。

```sh
git clone -b cross-platform-import https://github.com/1850VV/wc3env-127a ../wc3env-127a
cd bridge
WC3ENV_SRC=../../wc3env-127a/src python -m commander_bridge --backend fake --speed 4
# 打开 http://127.0.0.1:8790/ ，点「连接 假游戏服务器」
```

假服务器是 wc3env 自带的 `FakeServer`，配上本仓库的失落神庙测试世界（`bridge/commander_bridge/testworld.py`）：会采金、伐木、建造、训练并发出 wc3env 事件。会话、RPC 和协议校验都是 wc3env 自己的代码，和真游戏只差注入的 DLL。

### 3. 连接真游戏（Windows）

1. 按 wc3env-127a 的 README 准备：1.27a（构建号 1.27.0.52240）、64 位 Python 3.11+、编译好的 `wc3hook.dll`，在 `.env` 里设置 `WC3_GAME_DIR`，并 `pip install -e .`。
2. 确认游戏 `Maps` 目录里有 `(4)LostTemple.w3m`。
3. 启动：

```powershell
cd bridge
python -m commander_bridge --backend wc3env --opponent easy
# 打开 http://127.0.0.1:8790/ ，点「连接 魔兽争霸三」
# 测试开关：--launch 自动开局；--human-slot 0|1|2|3 指定出生点（南/西/北/东）；
# --speed-factor 2 交互窗口 = 实时 2× 可操作视角；4 以上或 --no-render 走步进加速
```

**自己开游戏（默认）**：点「连接 魔兽争霸三」后服务一直等，怎么打开的魔兽都行。没有指挥官组件（wc3env-127a 分支 `claude/attach-menu-game` 编译的 `wc3hook.dll`）的魔兽，服务发现 5 秒后自动装上，在主菜单里或游戏中都可以；也可以用桌面快捷方式「魔兽争霸三（指挥官）」（`tools\windows\bridge.ps1 shortcut` 创建）直接带组件打开。每开一局，游戏在 0:01 停住等接管；接管后，地图文件名带 Lost Temple 的（如 `(4)LostTemple.w3m`、`Lost Temple LV4.w3x`）按你的出生点自动套用「人族速矿二本 · 南/西/北/东方」，战术开；游戏中途才装组件时读不到地图名，就看城镇大厅是不是在失落神庙的出生点上；别的地图或种族只观察。一局打完回菜单再开下一局，会再接管。切屏暂停、加载、连接中断都不算错，服务会接着等、接着连，同一局重新接上时保留进度。以管理员权限运行的魔兽（比如经游戏启动器打开的），普通权限的服务装不了组件，会提示一次。断开只断指挥官，不关你的游戏。

**测试开关 `--launch`（默认关）**：打开后「连接」像以前一样由服务自己启动游戏、按控制台上的计划开局，下面这些选项只对它有效。

默认以实时模式、后台可见窗口打开：画面照常显示，切到浏览器也不会暂停，但窗口不接收你的鼠标键盘。想自己上手一起玩，加 `--window interactive`（正常窗口，失去焦点时游戏可能暂停）。指挥官只给时间轴上涉及的单位下命令。验收步骤见 [docs/实机验收.md](实机验收.md)。出生点由游戏决定，控制台会自动切换过去。**只在离线单机使用，不要用于战网或任何联网对局。**

> 2026-10-19 已通过 Windows 实机启动与浏览器连接验收，记录见 [本次报告、日志与截图](validation/2026-10-19-startup/README.md)。完整开局行为、选址、寻路和时序仍需逐项验收；启动通过不代表所有游戏行为都已验证。

## 目录

| 路径 | 内容 |
|---|---|
| `web/index.html`、`app.js`、`style.css` | 控制台界面：地图、小地图、状态、命令面板、时间轴、指令输入 |
| `web/sim.js` | 模拟核心：地图模型、寻路、选址、经济、事件执行；浏览器和 Node 共用 |
| `web/data/lost-temple.js` | 生成的地图与数值数据，勿手改 |
| `bridge/commander_bridge/engine.py` | 时间轴 → wc3env 命令；观测和事件 → 事件状态 |
| `bridge/commander_bridge/server.py` | 本地 HTTP 服务、游戏会话线程、服务器推送 |
| `bridge/commander_bridge/strategies.py` | 保存和读取策略（`strategies/` 下的 JSON） |
| `bridge/commander_bridge/testworld.py` | 给 wc3env FakeServer 用的失落神庙经济世界 |
| `tools/build_data.py` | 从 warcraft-commander 提取的数据重新生成 `lost-temple.js` |
| `tools/export_plan.js` | 导出带工地位置的默认计划（测试夹具） |
| `tools/windows/bridge.ps1` | Windows 上启动 / 停止 / 查看指挥官服务；`install` 注册计划任务，供远程启动；加 `-Lan` 对局域网开放控制台 |
| `tools/pc.sh` | 在 Mac / Linux 上通过 SSH 远程操作游戏电脑上的服务，并转发控制台端口 |

## 数据来源与假设

- 地图网格、物件、出生点：[warcraft-commander](https://github.com/1850VV/warcraft-commander) `commander/sandbox/map-data.json`，从发布的失落神庙地图提取。
- 单位数值：同仓库 `commander/commander-economy-data.js`，取自 1.27a 的 UnitBalance 和 HumanUnitFunc。
- 建筑占地：游戏 `war3.mpq` 的 `Units\UnitData.slk` 里每个建筑的 `pathTex` 字段，加上同一 MPQ 里的寻路 TGA。**1 像素 = 1 格 = 32 单位**；贴图里品红 `(255,0,255)` 挡路，蓝 `(0,0,255)` 能走但不能建造。地图 `war3map.wpm` 是 640×640 格、对应 20480 单位，印证了这个比例。核对记录在 [docs/validation/2026-10-19-building-footprint](validation/2026-10-19-building-footprint/README.md)。
- 每趟采金/伐木 10、伐木每下 1.1 秒来自单位数据；金矿每次进一个农民；**矿内停留 1 秒和每棵树 50 木是未校准的假设**。
- 不模拟单位之间的碰撞、战斗和维护费。
