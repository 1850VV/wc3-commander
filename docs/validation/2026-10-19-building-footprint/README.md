# 2026-10-19 建筑占地：从真实游戏文件核对

**结论：二维网格用的是游戏真实的寻路占地，1 格 = 32 单位。之前看起来偏大，是因为地图把整张贴图（不可建造的范围）画成了建筑；`Simple` 贴图外面还有 2 格「能走但不能建」的缓冲，金矿是 4 格。现在地图改画「实心建筑 + 虚线缓冲」。**

## 从真实文件读到的

- 地图 `(4)LostTemple.w3m` 的 `war3map.wpm`：**640×640 格**；地图边界 20480 单位 → 每格 32 单位。
- 游戏 `war3.mpq` 的 `Units\UnitData.slk`：每个建筑的 `pathTex` 字段，见下表。
- `war3.mpq` 里的寻路 TGA（24bpp，未压缩）只有两种颜色：
  - 品红 `(255,0,255)`：挡路，对应导出的 `walk_rows`
  - 蓝 `(0,0,255)`：可走但不可建，只出现在 `build_rows`
- `war3.mpq` 和 `War3Patch.mpq` 的 `UnitData.slk` 都查了，结果一致；`web/data/lost-temple.js` 的 `walk_rows`/`build_rows` 与 TGA 像素逐格一致。

## 界面改成什么样

- 实心块 = `walk` 格（真正挡路的建筑），虚线框 = 整张贴图（不能建造、但单位能走）。
- `sim.js` 新增 `bodyRect()` 算实心包围盒；选址、寻路、封家逻辑仍用原来的 `walk`/`build` 格，没有改变。
- 截图 [`ui.png`](ui.png)：大厅蓝色实心 384，外圈虚线到 512；祭坛实心 192、虚线到 320；金矿实心 256、虚线到 512。

## 怎么读的

- 用 `mpyq` 读 MPQ。地图文件开头是 `HM3W` 头，真正的 MPQ 从偏移 **512** 开始，切出来再读。
- `war3map.wpm` 前 16 字节是 `MP3W` + 版本 + 宽高；后面一字节一格。
- TGA 用 18 字节头读宽高和 bpp，再逐像素取 RGB。
- 这些都是临时脚本，没有留在仓库里。
