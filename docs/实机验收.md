# 第一次实机验收（Windows）

目标：确认默认开局的五个事件能在真游戏里按计划执行，时间轴状态和游戏画面一致。

已有记录：[2026-10-19 Windows 实机启动验收](validation/2026-10-19-startup/README.md)。本次完成第 1–4 步；第 5–6 步的完整行为与两分钟画面对照尚未验收。

## 1. 确认 wc3env 能用

在 `wc3env-127a` 目录：

```powershell
python -m pip install -e .
python -m wc3env --instances 1 --steps 20 --stepms 250 --speed 64
```

能打印出推进结果就说明游戏路径、`wc3hook.dll` 和版本校验都正常。报错时先按 wc3env-127a 的 README 修好这一步。

## 2. 拿到指挥官代码

和 `wc3env-127a` 放在同一级目录：

```powershell
git clone https://github.com/1850VV/wc3-commander
```

## 3. 确认地图

wc3env 会在游戏的 `Maps` 目录（含子目录）里找名为 `(4)LostTemple.w3m` 的文件，**必须正好一个**：

```powershell
Get-ChildItem -Recurse -Filter "(4)LostTemple.w3m" "$env:WC3_GAME_DIR\Maps"
```

没有就从 warcraft-commander 仓库的 `maps/` 复制进 `Maps`；有两个就删掉或改名多余的那个（同名的雪地 `.w3x` 不算）。

## 4. 启动

**省事的做法**：用 `tools\windows\bridge.ps1`，它会自己找 `.venv` 的 Python、检查游戏目录、停掉旧服务、把输出存进 `bridge\run.log`。在 Windows 桌面上：

```powershell
powershell -ExecutionPolicy Bypass -File tools\windows\bridge.ps1 start
```

想从另一台电脑通过 SSH 远程启动，先在 Windows 上注册一次计划任务（只在你登录时、在你的桌面会话里运行，没有定时触发）：

```powershell
powershell -ExecutionPolicy Bypass -File tools\windows\bridge.ps1 install
```

之后在 Mac 上（SSH 别名 `pc`）：`tools/pc.sh start` 启动并把 8790 端口转发到本机，`tools/pc.sh status` 看状态，`tools/pc.sh log` 看日志，`tools/pc.sh stop` 停止，`tools/pc.sh pull` 拉最新代码。直接在 SSH 里运行 Python 不行：那样服务跑在没有桌面的会话 0，游戏窗口出不来。

想在局域网里其他电脑直接打开控制台（例如 `http://<LAN_SERVER_IP>:8790/`，不用转发端口），给 `start` 或 `install` 加 `-Lan`。控制台**没有登录保护**，同一网络里谁都能开局，只在家里用。还需要 Windows 防火墙放行 8790 端口，要管理员权限，在「以管理员身份运行」的 PowerShell 里执行一次：

```powershell
New-NetFirewallRule -DisplayName "wc3-commander 控制台 8790（局域网）" -Direction Inbound -Protocol TCP -LocalPort 8790 -Profile Private -RemoteAddress LocalSubnet -Action Allow
```

只对「专用」网络、只对同一网段放行。不要了就删：`Remove-NetFirewallRule -DisplayName "wc3-commander 控制台 8790（局域网）"`。

下面是不用脚本时的手动做法。**必须用第 1 步装 wc3env 的那个 Python**（一般是 `wc3env-127a\.venv` 里的）。电脑上如果有好几份 wc3env，直接敲 `python` 可能用的是系统 Python，加载另一份 wc3env。那份旁边没有 `.env`，就会去默认的游戏目录找地图，报 `matched 0 files`。

先确认这个 Python 加载的是哪份 wc3env、游戏目录在哪（第二行应该是你的游戏目录）：

```powershell
cd wc3-commander\bridge
..\..\wc3env-127a\.venv\Scripts\python.exe -c "import wc3env; from wc3env.settings import settings; print(wc3env.__file__); print(settings().game_dir)"
```

然后用同一个 Python 启动，并把输出同时存进 `run.log`：

```powershell
..\..\wc3env-127a\.venv\Scripts\python.exe -u -m commander_bridge --backend wc3env 2>&1 | Tee-Object -FilePath run.log
```

Windows PowerShell 5.1 会把 Python 写到错误输出的每一行都标成红色的 `NativeCommandError`，比如 `GET /favicon.ico ... 404`。这只是显示方式，不是出错；真正的错误会带 `Traceback`。

打开 <http://127.0.0.1:8790/>，点「连接 魔兽争霸三」。游戏窗口会弹出（后台可见模式，不会因为切到浏览器而暂停），不要关它。

## 5. 对照检查（游戏时间）

| 时间 | 应该看到 |
|---|---|
| 0–5 秒 | 农民 1、2、3 离开去建祭坛、农场、兵营；农民 4、5 采金；主基地开始训练农民 |
| 约 15 秒 | 农民 6 出生并去采金；下一个农民开始训练 |
| 约 38 秒 | 第一个农场完工，人口上限 18 |
| 约 64 秒 | 祭坛、兵营完工，建造它们的农民回去采金 |
| 约 65 秒 | 祭坛开始训练大法师（第一个英雄免费） |
| 约 75 秒 | 兵营开始训练步兵 |

每一条同时看两边：时间轴上的状态和文字，和游戏画面是否一致。

## 常见问题

| 现象 | 处理 |
|---|---|
| 找不到 wc3env | 在 wc3env-127a 里 `pip install -e .`，或启动时加 `--wc3env ..\..\wc3env-127a\src` |
| map name ... matched 0 files / 2 files | 先用第 4 步的检查命令看游戏目录：不是你的游戏目录，就是用错了 Python（报错里的 wc3env 路径也能看出来，2026-10-19 就遇到过）；目录对了，再回到第 3 步 |
| 红色 `NativeCommandError`，但内容是 `GET ... 404` 之类的访问记录 | 不用管，见第 4 步 |
| 版本或哈希校验失败 | 游戏不是 1.27.0.52240 的原版文件，wc3env 会拒绝注入 |
| 事件一直「等待资源」 | 正常的话会自己开始；超过 20 秒不动，截图时间轴和游戏资源栏 |
| 「游戏没有开工，重试」反复出现 | 选址或路径问题，截图工地附近的游戏画面。同一个建造事件让游戏造出多座同类建筑，是 2026-10-19 修过的认领问题，请记下事件名和时间 |
| 「游戏拒绝在指定位置建造」 | 地图上放的位置在游戏里建不了（被占、不平或挡路），换个位置 |
| 时间轴显示完工但画面没有建筑 | 记下事件名和时间，这是需要修的 bug |

停止：点控制台的「断开」，或在终端按 Ctrl+C。只在离线单机使用。
